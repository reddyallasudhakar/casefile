# F2: Can a 0.5B model match Gemini at sorting claim documents?

**Task.** Classify a page from an Indian health-insurance claim file into one of 10 document
types (settlement letter, rejection letter, cashless pre-auth denial, query letter, policy
schedule, hospital bill, discharge summary, medical report, health card, other).

## In short

- **Yes.** A fine-tuned **Qwen2.5-0.5B** gets **124/124 on clean text, matching Gemini 3.1 Pro**,
  and 98.4% on the hardest variant (OCR'd phone/scan images with type-revealing headings
  hidden), statistically indistinguishable from Gemini's 100%.
- **Fine-tuning, not prompting or size, closed the gap.** On realistic input, the best
  *prompted* model (Qwen 3B, zero-shot or few-shot) reaches 79.8%; every fine-tuned size
  reaches 98–99%.
- **The smallest model is the sweet spot:** 8 minutes to train on one GPU, 0.2 s per page,
  a 34 MB adapter. Small enough to run inside a client's own cloud, or on a laptop.

| Qwen 0.5B | Few-shot | 25.8% | 20.2% | 21.8% | 18.5% |
| Qwen 0.5B | Fine-tuned | **100.0%** | **100.0%** | **99.2%** | **98.4%** |
| Qwen 1.5B | Zero-shot | 71.8% | 54.8% | 61.3% | 50.8% |
| Qwen 1.5B | Few-shot | 76.6% | 60.5% | 68.5% | 57.3% |
| Qwen 1.5B | Fine-tuned | **100.0%** | **99.2%** | **100.0%** | **99.2%** |
| Qwen 3B | Zero-shot | 92.7% | 79.8% | 87.9% | 79.8% |
| Qwen 3B | Few-shot | 92.7% | 82.3% | 92.7% | 79.8% |
| Qwen 3B | Fine-tuned | **100.0%** | **98.4%** | **100.0%** | **99.2%** |
| Gemini 3.5 Flash | Zero-shot | 100.0% | 100.0% | 100.0% | 100.0% |
| Gemini 3.1 Pro | Zero-shot | 100.0% | 100.0% | 100.0% | 100.0% |
| Keyword rules | — | 54.8% | 52.4% | 53.2% | 51.6% |

## What the results say

1. **Prompting barely helps; fine-tuning transforms.** Adding one example per type
   (few-shot) gives +0–7 points. Fine-tuning gives +7 to +82 points, ending at 98–100% for
   every size.
2. **Fine-tuning beats size.** On realistic input, a fine-tuned 0.5B (98.4%) beats the
   best-prompted 3B (79.8%) by almost 19 points at a sixth of the size.
3. **The lift is largest exactly where input is hardest.** Untrained models lean on the
   headings (hiding them costs Qwen 3B 13 points); training on pages with and without
   headings, clean and OCR'd, made the fine-tuned models robust to both.
4. **After fine-tuning, size buys nothing measurable.** All three sizes make 0–3 errors in
   496 page-variant predictions, so the smallest wins on speed and cost.
5. **Frontier models find this task easy.** Both Geminis score 100% on every variant, so
   "match Gemini" here means "reach 100%, or be statistically indistinguishable from it".

### Against Gemini: McNemar's exact test

Counting only the pages where exactly one of the two models was right (fine-tuned Qwen
right / Gemini 3.1 Pro right). If both models were equally good, those would split like
coin flips; p is the chance of a split this lopsided by luck.

| Fine-tuned | Clean | Titles hidden | OCR | OCR + titles hidden |
|---|---|---|---|---|
| 0.5B | 0 / 0 (identical) | 0 / 0 (identical) | 0 / 1, p = 1.00 | 0 / 2, p = 0.50 |
| 1.5B | 0 / 0 (identical) | 0 / 1, p = 1.00 | 0 / 0 (identical) | 0 / 1, p = 1.00 |
| 3B | 0 / 0 (identical) | 0 / 2, p = 0.50 | 0 / 0 (identical) | 0 / 1, p = 1.00 |

No gap is statistically real (all p ≥ 0.50).

### Cost and speed

| | Qwen 0.5B | Qwen 1.5B | Qwen 3B |
|---|---|---|---|
| Training time (one NVIDIA L4) | 8 min | 23 min | 40 min |
| Trainable parameters (LoRA) | 8.8M (1.75%) | 18.5M (1.18%) | 29.9M (0.96%) |
| Adapter size | 34 MB | 71 MB | 115 MB |
| Inference (one L4, fp32) | 0.2 s/page | 0.55 s/page | 1.1 s/page |

Total GPU cost for all fine-tuning and evaluation: about $1–2 on Google Cloud.

### The remaining errors

All are between the near-neighbour types the label guide flags as easy to confuse:

- **0.5B:** medical report → discharge summary (×2, OCR'd), query letter → other (×1).
- **1.5B and 3B:** rejection letter ↔ cashless pre-auth denial (×5, all with headings hidden).
  This is the distinction that matters most in practice: a cashless denial is not a claim
  rejection, and the next step is different.

## How it was tested

- **Data:** 800 synthetic claim pages (80 per type) generated from 314 sampled claim cases.
  Every fact on a page comes from its case, all names are fictional, and no real customer
  data is used ([synth/](../synth)).
- **Split by case, not by page** (70/15/15): no test page shares a patient, hospital or
  amounts with training data. Test set: 47 cases, 124 pages, 10–14 per type
  ([bench/splits.json](../bench/splits.json)). It was never used for training or prompt tuning.
- **Four versions of every test page:**
  **clean** text; **titles hidden** (heading lines naming a type replaced by
  `[heading removed]`, [bench/mask_titles.py](../bench/mask_titles.py)); **OCR**
  (Google Cloud Vision reading a degraded phone-photo or scanner image of the page,
  [bench/ocr.py](../bench/ocr.py)); and **OCR + titles hidden**.
- **Methods** ([bench/baselines.py](../bench/baselines.py)): every model gets the same prompt,
  the 10 label definitions plus the page. Qwen answers by **label scoring**: the model's
  log-probability of each of the 10 labels, taking the highest, so it can't produce an
  invalid answer. *Few-shot* adds one 300-character example page per type from the
  training set. Gemini answers in free text.
- **Fine-tuning** ([bench/finetune.py](../bench/finetune.py)): LoRA rank 16 on every attention
  and MLP projection; one epoch over 2,276 examples (569 training pages × the four
  variants); loss on the answer tokens only; lr 2e-4 with warmup and cosine decay;
  effective batch 16; bf16. Training logs: `adapters/qwen-*/train_log.json`.
- **Scoring** ([bench/score.py](../bench/score.py)): accuracy with a Wilson 95% interval,
  macro-F1, invalid-output rate, confusion matrix, and McNemar's exact test between models.

### Success bar, set before any results (2026-10-23)

> The fine-tuned Qwen2.5-0.5B-Instruct matches or beats Gemini Flash on the test set:
> accuracy ≥ Gemini's on the same 124 pages with the same clean input, with a McNemar test
> reported alongside; a lower but non-significant score is reported as "statistically
> indistinguishable", not as a pass.

**Result: met.** 124/124 on clean text, identical to Gemini 3.5 Flash and Gemini 3.1 Pro.

## Limitations

- **One generator.** Every page, training and test, was written by Gemini 3.5 Flash. A
  fine-tuned model may partly have learned that writer's style. The decisive next test is a
  set of real, de-identified claim pages (kept private).
- **Simulated degradation.** The phone and scan effects are our own; real uploads can be worse.
- **Small test set.** With 124 pages, one page is 0.8 points, which is why every comparison
  carries a McNemar test rather than relying on raw accuracy.
- **Speed measured on a GPU.** Laptop latency for the 0.5B hasn't been measured yet.

## Reproduce

```bash
uv sync
uv run python -m bench.split                                         # the frozen split
uv run python -m bench.ocr && uv run python -m bench.mask_titles     # test variants
uv run python -m bench.finetune --size 0.5B                          # on a GPU
uv run python -m bench.baselines qwen-finetuned --variant ocr-masked # predictions
uv run python -m bench.score preds/qwen-finetuned-0.5B__ocr-masked.jsonl --compare preds/gemini-pro__ocr-masked.jsonl
uv run python -m bench.report                                        # this page's grid and chart
```
